## Detailed Notes

### 1. Text-Based vs. Graphical User Interfaces
* **Text vs. Graphics:** We discussed the pros and cons of utilizing text-based interfaces compared to graphical interfaces. 
* **Robustness of Text:** Text is inherently more robust and universally compatible. Not all environments have a display monitor or graphical environment (such as headless servers), making text the most reliable fallback.
* **Machine Communication:** Ultimately, text is the foundational method for interacting with a machine—feeding it plain text commands and receiving parsable text output.

### 2. ASCII Art and Tree Representations
* **ASCII Trees:** We explored the concept of representing hierarchical data (like file systems or data structures) using an ASCII tree format.
* **Handling Screen Real Estate:** A common issue with generating ASCII trees is when the output exceeds the terminal window size. To avoid excessive scrolling and improve readability, the drawing pattern or depth of the tree should be adapted to fit within standard console constraints.

### 3. Secure Shell (SSH) and Daemons
* **What is SSH?** SSH (Secure Shell) is a cryptographic network protocol used to operate network services securely over an unsecured network. It is predominantly used for remote command-line login and execution.
* **What is SSHD?** We covered `sshd`, where the 'D' stands for *daemon*. A daemon is a background process that runs continuously to answer requests for services. In this context, `sshd` is the server-side program that listens for incoming SSH connections.

### 4. Thread Management in Programming
* **Gracefully Stopping a Thread:** We discussed the proper approach to stopping or terminating a thread in concurrent programming. Instead of forcefully killing a thread—which can lead to resource leaks or corrupted states—the best practice is to signal the thread (e.g., via a boolean flag or interrupt), giving it time to wrap up its current task, release held resources, and terminate gracefully.

### 5. List Comparison and Visual Connections in JavaFX
* **Algorithmic Approaches to Matching:** When identifying common elements between two lists, a basic nested-loop comparison results in an inefficient O(n × m) time complexity. To improve lookup performance, especially for larger datasets, a `HashMap` can be used to associate values from the second list with their indexes, drastically reducing the search time.
* **Defining Match Rules:** Before implementing the comparison logic, developers must strictly define the matching criteria. This includes deciding whether the comparison should be case-sensitive, if whitespace should be ignored, how null values are handled, and how duplicate items (one-to-many or many-to-many relationships) should behave visually.
* **Drawing Connections (Arrows):** To visually connect matched items placed on opposite sides of a window, we calculate the exit point of the left item and the entry point of the right item. Using JavaFX `Line` objects and trigonometry (like `Math.atan2`), we can accurately compute the angle needed to draw both the main line shaft and the arrowhead pointing to the destination.
* **Separation of Concerns:** A maintainable application clearly separates its responsibilities into three parts: the data (raw lists), the logic (matching algorithm), and the presentation (JavaFX visuals). This decoupled design ensures the algorithm can be tested quickly and independently without requiring the graphical interface to launch.
