## Detailed Notes

### 1. Java Artifacts and Build Tools (JAR & Maven)
* **.jar Files:** A Java ARchive (JAR) file is essentially a ZIP format file used to aggregate many Java class files, associated metadata, and resources into a single file for distribution.
* **Maven:** Discussed Maven as a build automation tool used primarily for Java projects. It simplifies the build process by automatically fetching dependencies, managing versions, and handling the project lifecycle.
* **Java Properties:** In Java, properties refer to configuration parameters that are often stored as key-value pairs. They allow applications to read configuration data without hardcoding it into the source code.

### 2. CI/CD Pipelines and Deployment Concepts
* **CI/CD Overview:** Explored the concepts of Continuous Integration (CI) and Continuous Deployment/Delivery (CD). 
    * **Integration (CI):** The practice of frequently merging code changes into a central repository (e.g., via `git pull` and push), followed by automated builds and tests.
    * **Deployment (CD):** The automated process of pushing the integrated code to a staging or production environment (storing/hosting).
* **Install vs. Deploy:**
    * **Install:** Refers to setting up software locally on a machine (e.g., installing Git).
    * **Deploy:** Refers to hosting or placing the application on a server or remote environment (e.g., GitHub, cloud servers) so it can be accessed.

### 3. Character Encodings (UTF-8 vs UTF-16)
* **Character Set Definition:** A character set is essentially a standardized mapping that assigns specific numerical values to human-readable characters.
* **UTF-8:** A widely used character encoding that represents characters in 1 to 4 bytes. It is the standard for the web.
* **UTF-8 vs. UTF-16 (Cost):** 
    * **UTF-8** is highly efficient for Western languages as it uses only 1 byte per character, saving storage and bandwidth "costs". 
    * **UTF-16** uses 2 or 4 bytes per character, which can incur a higher memory and storage cost for standard text compared to UTF-8.

### 4. Java Compatibility (Backward & Runtime)
* **Backward Compatibility:** Java is designed with backward compatibility in mind. For example, if you compile code on Java 21, it is guaranteed to execute flawlessly on a newer runtime environment like Java 25.
* **Source Version vs. Runtime Version:** 
    * **Source Version:** The version of the Java language used to write the code.
    * **Runtime Version:** The version of the Java Virtual Machine (JVM) executing the code. The runtime version must always be greater than or equal to the compiled source version.

### 5. Session Management
* **What is Session Management?** Briefly discussed how sessions work. Since HTTP is stateless, session management is the mechanism used to track a user's state and interactions across multiple requests, often using session IDs.

### 6. Testing Frameworks (JUnit & Unit Testing)
* **Unit Testing:** The practice of testing individual, isolated components or "units" of software (like a single method) to ensure they function as expected.
* **JUnit:** A popular testing framework for Java used to write and execute unit tests automatically.

### 7. Java UI Technologies (FXML)
* **FXML Overview:** FXML is an XML-based language used to define user interfaces in JavaFX applications, keeping the UI structure separate from the application's core logic.
